# rubric

Каждые 30 минут применяет правила из `rules.toml` к новым операциям [Zenmoney](https://zenmoney.ru). Нужен, чтобы история не зарастала тем, что банки присылают криво: округления, оплаты через перевод себе, переводы в другую валюту, покупки с полным возвратом.

Код знает только **типы** правил. Конкретные счета, получатели, пороги и категории задаются в `rules.toml`; шаблон — `rules.example.toml`.

## Что умеет

| Тип в `rules.toml` | Что делает | Пример |
|---|---|---|
| `[[transfer]]` | превращает трату в перевод на счет | округления T-Bank → копилка |
| `[[fx_transfer]]` | склеивает трату и поступление в другой валюте в один перевод | рубли с карты → свой счет в GEL |
| `[refund]` | удаляет покупку вместе с ее полным возвратом | возврат товара на маркетплейсе |
| `[[category]]` | ставит категорию по сумме | перевод себе до 700 ₽ — такси, дороже — доставка |
| `[[notice]]` | только пишет в лог | крупный перевод себе: куда? |

Чего не делает:
- не подбирает категории — это делает сам Zenmoney по получателю;
- не склеивает переводы между своими счетами в одной валюте — их склеивает Zenmoney;
- не трогает ручные операции и холды.

## Гарантии

- **Каждая операция решается один раз.** Id обработанных операций хранятся в `data/state.json`. Если после autopilot ты поправил операцию руками, он ее больше не тронет.
- **Ждет, пока операция устоится.** Операция рассматривается через `settle_days` после своей даты и не позже `lookback_days`.
- **Несклеенный перевод не трогается.** Если на другом своем счете есть поступление на ту же сумму в пределах 2 дней, это перевод, который Zenmoney вот-вот склеит. Никакое правило такую трату не трогает.
- **Ни одна правка не двигает баланс счетов.** Это проверяется до записи (иначе это ошибка в коде) и после нее, сверкой с сервером.
- **Не больше `max_writes_per_run` правок за запуск.** Если запланировано больше, ничего не пишется. Защищает от массовой порчи, если ошибся в правиле или Zenmoney поменял формат данных.
- **Спорное остается тебе.** Сервис не трогает, а пишет в лог:
  - два подходящих поступления для одной склейки;
  - возврат к покупке, которая еще на холде;
  - крупный перевод себе.
- **Ошибка в `rules.toml` останавливает запись.** Неизвестный ключ, сломанный regex, переименованный в Zenmoney счет или категория — ни одной записи, пока не исправишь.

### Возвраты — самое строгое правило

Удаление в Zenmoney **необратимо**: удаленную операцию восстановить нельзя, `undo` создает ее копию с новым id. Поэтому пара удаляется, только если:

- счет тот же, сумма точно та же. Частичный возврат остается доходом в категории покупки;
- магазин тот же: названия совпадают, одно — начало другого («Whoosh» / «WHOOSH_SBP») или оба в одной группе `merchant_aliases`. Если получателя нет, берется комментарий;
- возврат пришел не раньше покупки и не позже чем через `max_days`;
- из нескольких одинаковых покупок берется **ближайшая перед возвратом**, чтобы удалилась покупка нужного месяца;
- получатель не похож на человека (`skip_payee_regex`). Если «Анна К.» вернула долг, это не возврат;
- покупка не на холде. Иначе только запись в лог.

Возврат в другой валюте не удаляется: из-за курса суммы в рублях разные, и удаление сдвинуло бы баланс.

## Установка

Нужны Docker с Compose и git. Python не нужен.

```sh
git clone https://github.com/Resetand/rubric.git && cd rubric
make init     # создаст .env (права 0600) и rules.toml из примера
# впиши ZENMONEY_TOKEN в .env, свои счета и получателей — в rules.toml
make plan     # покажет, что записал бы сейчас; в Zenmoney ничего не пишет
make start    # запуск каждые 30 минут в фоне
```

Обновление: `make update` — `git pull` и перезапуск.

Локально без Docker: `uv run python -m autopilot plan` (или `run`, `loop`).

Запускать autopilot одновременно в двух местах нельзя: правки делались бы дважды.

## Эксплуатация

| Команда | Что делает |
|---|---|
| `make plan` | что записал бы сейчас |
| `make run` | применить один раз |
| `make logs` | лог: что записано, что требует решения, ошибки |
| `make undo JOURNAL=data/journal/<время>.json` | откатить запуск |
| `make stop` / `make start` | остановить / запустить |
| `make test` | тесты |

- **Журнал правок:** `data/journal/<время>.json` — исходные и новые версии операций каждого запуска. Откат возвращает измененным операциям старое содержимое, удаленные восстанавливает копиями и отменяет компенсацию баланса.
- **Копия Zenmoney:** `data/mirror.json`. Первый запуск скачивает все, дальше приходят только изменения — обычно доли секунды. Раз в неделю копия скачивается целиком заново, на всякий случай. Удалить `mirror.json` безопасно.
- **`data/state.json` удалять нельзя.** Без него правила заново рассмотрят последние `lookback_days` и могут перезаписать твои ручные правки за этот период.
- Все файлы в `data/` доступны только владельцу: там вся финансовая история.
- **Новое правило:** допиши его в `rules.toml`, запусти `make plan` и посмотри, что оно сделает. Поля каждого типа описаны в `autopilot/config.py`.

## Устройство

```
autopilot/
  zenmoney.py   API: diff (все или изменения) и запись
  mirror.py     локальная копия с инкрементальной синхронизацией
  config.py     rules.toml → типизированные правила, строгая проверка
  engine.py     чистый планировщик: данные + правила + дата + обработанные → правки
  __main__.py   CLI, запись, сверка, журнал, state.json
rules.example.toml
```

`tests/test_replay.py` прогоняет правила по личной истории до ручной очистки и требует, чтобы каждая предложенная правка совпала с тем, что было утверждено вручную. Данные для него лежат только локально, без них тест пропускается.
